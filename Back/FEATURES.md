# 백엔드 기능 목록

현재 컨트롤러·서비스·운영 스크립트를 기준으로 작성했습니다. API 기본 경로는 `/api/v1`이며 표에서는 생략합니다. `로그인`은 USER·AUTHOR·ADMIN 모두, `문제 소유자`는 역할과 상관없이 해당 문제를 작성한 사용자를 뜻합니다. ADMIN은 모든 문제를 관리할 수 있습니다.

## 1. 계정과 인증

| API | 권한 | 기능 |
|---|---|---|
| `POST /auth/register` | 공개 | 회원가입 후 JWT와 사용자 정보 반환 |
| `POST /auth/login` | 공개 | 이메일·비밀번호 확인 후 JWT와 사용자 정보 반환 |
| `GET /users/me` | 로그인 | 내 계정·역할·XP·레벨·rating·가입일·해결 문제 수 |
| `GET /users/:username` | 공개 | 공개 프로필: 사용자 이름·레벨·XP·전체 순위·해결 문제 수·공개 문제 중 해결 목록·가입일·배지 |
| `PATCH /auth/password` | 로그인 | 현재 비밀번호 확인 후 변경, 기존 JWT 모두 무효화하고 새 JWT 반환 |
| `PATCH /auth/username` | 로그인 | 사용자 이름 변경 후 새 JWT 반환(기존 JWT 유지) |

- 이메일 소문자 정규화, 이메일·사용자 이름 중복 거절(409). 사용자 이름은 입력한 대로 저장하지만 대소문자만 다른 이름(`Foo`·`foo`)과 예약 이름 `boj_import`도 대소문자 없이 거절합니다. 사용자 이름은 영문·숫자·밑줄 3–30자, 비밀번호는 10–128자입니다.
- 사용자별 salt와 scrypt로 비밀번호를 해시하고 상수 시간 비교로 검증합니다. 비밀번호 해시는 응답에 포함하지 않습니다.
- 가입 시 USER이며 AUTHOR는 문제 작성자, ADMIN은 관리자입니다. JWT 기본 유효 기간은 15분이며 `JWT_ACCESS_EXPIRES_IN`에 `15m`처럼 양의 정수와 s·m·h·d 단위로 조정할 수 있습니다. 다른 형식은 시작할 때 거절합니다.
- 인증 요청마다 DB의 현재 역할과 `tokenVersion`, 정지 여부를 확인합니다. 관리자 역할 변경·계정 정지, CLI 승격, 비밀번호 변경은 기존 JWT를 무효화하고, 정지된 계정은 로그인할 수 없습니다(403).
- 공개 프로필은 사용자 이름을 대소문자 없이 찾으며 이메일·역할·rating을 반환하지 않습니다. `solvedCount`는 랭킹과 같이 전체 해결 수이고 `solvedProblems`에는 공개 문제만 담습니다.
- 비밀번호·사용자 이름 변경은 각각 분당 5회입니다. 틀린 현재 비밀번호는 400입니다(401은 웹이 로그아웃으로 처리). 사용자 이름은 가입과 같은 형식·대소문자 무시 고유성·예약 이름 규칙을 따릅니다.

## 2. 문제와 테스트케이스

| API | 권한 | 기능 |
|---|---|---|
| `GET /problems` | 공개 | 공개 문제 목록, 난이도·태그(`tag`) 필터, 페이지 조회, 문제별 푼 사람·정답률 |
| `GET /problems/by-slug/:slug` | 공개 | 공개 문제 설명·제한·예제·태그·해설과 푼 사람·정답률 조회 |
| `GET /problems/:slug` | 공개 | 기존 상세 주소의 호환 경로; `mine`은 관리 경로가 우선 |
| `POST /problems` | 로그인 | 문제·테스트케이스·최초 버전 생성; 공개 상태 생성은 ADMIN만 가능. ADMIN이 아니면 초안(기업 전용 포함)은 계정당 50개까지(보관 문제는 세지 않음, 보관에서 초안으로 되돌릴 때도 검사), 시간 제한 × 테스트 개수는 120초까지(수정할 때도 검사) |
| `GET /problems/mine` | 로그인 | 내 문제 최신 100개(`isPrivate` 포함), ADMIN은 전체 중 최신 100개 |
| `GET /problems/:id/manage` | 문제 소유자/ADMIN | 비공개 테스트케이스를 포함한 관리 상세 |
| `PATCH /problems/:id` | 문제 소유자/ADMIN | 내용·난이도·제한·테스트케이스 수정 및 버전 증가 |
| `PATCH /problems/:id/status` | 문제 소유자/ADMIN | DRAFT·PUBLISHED·ARCHIVED 전환; PUBLISHED는 ADMIN만 가능, 기업 전용 문제는 불가(400) |

- 로그인한 누구나 문제를 만들 수 있습니다. 공개 목록에 올리려면 관리자 검수(PUBLISHED 전환)를 거칩니다. AUTHOR 역할은 기존 계정 호환용이며 출제 권한에 차이가 없습니다.
- 기업 테스트 전용 문제(`isPrivate`)는 공개 목록·상세·일반 제출에 나오지 않고 공개로 바꿀 수 없습니다. 소유자·ADMIN만 관리하고 검증 제출할 수 있으며, 기업 테스트에 공개 문제와 함께 출제할 수 있고, 응시자는 응시 중에만 그 시험을 통해 보고 제출합니다(6-2절). 공개 문제를 기업 전용으로 바꾸면(ADMIN 수정 포함) 초안으로 내려갑니다.

- 본문·입력 설명·출력 설명을 Markdown으로 저장합니다. 난이도는 BEGINNER/EASY/MEDIUM/HARD/EXPERT입니다.
- 태그(`tags`)는 자유 문자열 0–10개, 각 1–30자이며 앞뒤 공백을 지운 뒤 중복을 거절합니다. 목록의 `tag`는 대소문자를 포함해 정확히 일치하는 태그 하나로 거릅니다. 웹 목록은 전체를 받아 같은 조건으로 브라우저에서 거릅니다.
- 해설(`editorialMarkdown`, 최대 10만 자, 기본 빈 문자열)은 공개 상세에 포함됩니다. 웹은 해당 문제를 정답으로 푼 사용자에게 바로 보여 주고, 그 외에는 ‘스포일러 보기’를 누른 뒤 보여 줍니다. 누구나 확인 후 볼 수 있으므로 서버 권한 경계가 아니라 스포일러 방지 표시입니다.
- 푼 사람(`solverCount`, 정답을 받은 서로 다른 사용자)과 정답률(`acceptanceRate`, 채점이 끝난 제출 중 정답 비율, 제출이 없으면 null)은 목록과 상세가 같은 집계를 씁니다. 대기·채점 중·시스템 오류·취소 제출은 제외합니다.
- 문자열 필드·태그는 NUL과 짝 없는 서로게이트를 400으로 거절합니다.
- 공개 목록은 최신 생성순(동일 시각이면 ID 내림차순), 기본 20개·최대 1,000개입니다. 이어 읽기는 응답의 `nextCursor`를 다음 요청의 `cursor`로 전달하고, `null`이면 끝납니다. 기존 `page` 조회(최대 1,000,000)도 유지합니다. 공개 상세에는 `isSample=true`인 예제만 반환합니다.
- 시간 제한은 기본 1,000ms, 범위 100–60,000ms이며 메모리는 기본 256MB, 범위 16–4,096MB입니다.
- 테스트케이스는 1–100개이고 입력·기대 출력 각각 최대 100만 자입니다. 기대 출력은 후행 ASCII 공백을 제외한 UTF-8 크기가 999,999바이트 이하여야 합니다. 빈 출력과 비공개 테스트만 있는 구성도 허용합니다. 순서·예제 여부·score(1–10,000)를 저장하며 부분 점수 계산은 없습니다.
- 생성 시 `status`를 생략하면 DRAFT이며 null은 거절합니다. 수정에서 생략한 필드는 유지하고 빈 수정·필수 필드의 null을 거절합니다. slug는 수정할 수 없습니다.
- 수정·상태 변경은 버전 일치 조건 없이 마지막 저장을 적용합니다. 오래 열어 둔 화면의 저장도 덮어쓸 수 있으며, 공개 전환은 요청 처리 시점의 최신 내용을 대상으로 합니다.
- 내용 수정마다 `currentVersion`을 증가시키고 제한·태그·해설·전체 테스트케이스를 `problem_versions`에 불변 스냅샷으로 저장합니다. 태그·해설만 바꿔도 버전이 오르고, AUTHOR의 공개 문제 수정 규칙도 같습니다. 상태만 변경할 때는 버전을 증가시키지 않습니다.
- AUTHOR가 공개 문제를 수정하면 초안으로 돌아가 관리자 재검수가 필요합니다. ADMIN 수정은 공개 상태를 유지합니다.
- 각 필드 제한과 별도로 JSON 요청 전체는 **16MiB** 이하입니다. 여러 대형 테스트케이스의 합계에도 적용됩니다.
- 웹 공개 주소는 `/problems/view/:slug`입니다. `mine`, `new` 같은 slug도 관리 경로와 충돌하지 않습니다.

## 3. 제출과 재채점

| API | 권한 | 기능 |
|---|---|---|
| `POST /problems/:problemId/submissions` | 로그인 | 공개 문제에 제출하고 채점 큐 등록, HTTP 202 반환. 공개 전 문제는 소유 작성자/ADMIN만 검증용(`isTest`)으로 제출. 분당 20회, ADMIN이 아니면 채점 대기·진행 중인 제출은 계정당 3개까지(넘으면 429) |
| `GET /submissions` | 로그인 | 내 제출 목록(검증용 제외), 문제 ID 필터, 페이지 조회 |
| `GET /submissions/:id` | 제출자 본인, 문제 소유자/ADMIN | 판정·소스 코드·실행 정보·공개 예제 출력 |
| `GET /problems/:problemId/submissions` | 문제 소유자/ADMIN | 문제별 전체 제출(검증용 포함, 제출자 이름), 상태 필터, 페이지 조회. 소스는 상세에서만 |
| `POST /submissions/:id/rejudge` | 문제 소유자/ADMIN | 재채점, HTTP 202 반환. 분당 20회, 일괄 재채점처럼 새 제출 뒤에 처리 |
| `POST /problems/:problemId/rejudge` | 문제 소유자/ADMIN | 오래된 제출부터 최대 200건 재채점. `{ requeued, skipped, remaining, next }`를 돌려주며 `next`를 `after`로 넘겨 이어서 처리. 대기·채점 중인 제출은 건너뜀 |

- 지원 언어는 C/CPP/JAVA/PYTHON/JAVASCRIPT/TYPESCRIPT/GO/RUST, 소스 크기는 1–200,000자입니다.
- 제출 생성 당시 문제 버전으로 채점합니다. 재채점은 공개 중인 문제면 **현재 버전**(고친 테스트)으로, 초안·보관 문제면 검수 전 테스트가 다른 사용자의 결과·XP를 바꾸지 않도록 제출 당시 버전으로 돌립니다. 검증용 제출은 항상 현재 버전입니다.
- 단건·일괄 재채점 작업은 BullMQ priority를 붙여 새 제출보다 뒤에 처리합니다(복구 타이머가 다시 넣은 작업은 priority 없음).
- 검증용 제출(`isTest`)은 해결 기록·XP·미션·문제 통계·내 제출 목록(학습 기록)에 넣지 않습니다. 문제를 나중에 공개해도 소급하지 않습니다.
- 목록은 최신 제출순(동일 시각이면 ID 내림차순), 기본 20개·최대 1,000개입니다. `nextCursor`·`cursor` 이어 읽기도 지원하며, 이때 기존 페이지 번호(최대 1,000,000)의 OFFSET은 적용하지 않습니다. 목록 쿼리는 소스·디버그 출력을 읽지 않습니다. 소스는 본인과 해당 문제의 소유 작성자·ADMIN 상세에만 반환하고, 그 외 사용자의 상세 조회는 404입니다.
- 응답에는 상태, 문제 버전, 채점 세대, 실행 시간·메모리, 통과/전체 테스트 수, 컴파일 출력, 채점 메시지, 생성/수정 시각이 포함됩니다.
- 재채점은 세대를 증가시키고 이전 시도·판정 정보를 초기화합니다. 이전 워커가 뒤늦게 보낸 결과는 거절합니다.
- 최초 큐 등록 실패는 SYSTEM_ERROR로 저장하고 503을 반환합니다. 재채점 큐 등록 실패는 복구 작업이 재시도하도록 QUEUED를 유지합니다.

진행 상태는 QUEUED/JUDGING, 최종 상태는 ACCEPTED, WRONG_ANSWER, TIME_LIMIT_EXCEEDED, MEMORY_LIMIT_EXCEEDED, RUNTIME_ERROR, COMPILE_ERROR, OUTPUT_LIMIT_EXCEEDED, SYSTEM_ERROR, CANCELLED입니다. CANCELLED는 내부 결과 계약의 상태이며 사용자 취소 API는 없습니다.

- 본인 상세의 `debugOutputs`에는 실행된 공개 예제 최대 5개의 stdout·stderr 앞 1,000바이트와 잘림 여부를 반환합니다. 비공개 테스트 출력은 숨기고 재채점 시 초기화합니다.
- DB에 저장할 수 없는 NUL·불완전한 서로게이트는 진단 표시에서 대체 문자로 변환합니다. 실제 정답 비교에 사용하는 바이트는 바꾸지 않습니다.
- 본인 상세의 `sampleTestCases`는 해당 출력과 대응하는 **제출 당시 버전**의 공개 예제 입력·기대 출력·원래 테스트 번호(`testCase`)를 반환합니다. 문제 수정·보관 후에도 최신 문제의 예제로 대체하지 않습니다. 버전이나 출력이 없으면 빈 배열이며 비공개 테스트는 포함하지 않습니다.

## 4. XP·레벨·랭킹

| API | 권한 | 기능 |
|---|---|---|
| `GET /rankings` | 공개 | XP 상위 100명의 사용자 이름·레벨·XP·rating·해결 문제 수·순위(`rank`) 배열 |
| `GET /rankings?page=&limit=` | 공개 | 같은 정렬의 쪽 조회(`limit` 최대 100, 기본 20); `items`·`page`·`limit`·`total`·`totalPages` 반환 |

- 사용자·문제별 첫 정답에만 XP를 지급합니다. 추가 정답과 동일 판정 재전송에는 중복 지급하지 않습니다.
- 현재 채점 진행 상태와 별도로 제출별 마지막 정상 정답 근거(`accepted_for_xp`)를 보존합니다. 추가 정답 제출이 재채점 오류 상태여도 다른 제출의 오답 확정만으로 XP를 잘못 회수하지 않습니다.
- 정상 학습 완료 근거(`completed_for_learning`)는 오답/컴파일 오류도 보존하며 재채점으로 지우지 않습니다. 미션과 홈/프로필의 중간 학습일 및 동일 streak 보상이 재채점 대기 중 분리되지 않습니다. 적용/backfill 한계는 `docs/missions.md`를 따릅니다.
- 첫 정답의 문제 버전 난이도에 따라 BEGINNER 10, EASY 20, MEDIUM 40, HARD 80, EXPERT 160 XP를 지급합니다.
- 레벨은 `1 + floor(XP / 100)`입니다. 랭킹은 XP 내림차순, 동점일 때 가입일 오름차순입니다. `GET /users/me`의 `rank`는 같은 정렬로 센 1부터의 전체 순위이며 상위 100명 밖이어도 제공합니다.
- 재채점 대기·서버 오류(`SYSTEM_ERROR`)·취소(`CANCELLED`)는 기존 정답 근거와 XP를 유지하며, 최초 제출의 오류에는 XP를 지급하지 않습니다. 정상 채점으로 마지막 유효 정답이 오답·제한 초과·실행/컴파일 오류 등으로 확정된 경우에만 해결 기록과 XP를 회수합니다.
- rating은 저장·조회 필드만 있으며 별도 계산·갱신 로직은 없습니다.

- 운영 조회에는 waiting/active/delayed/failed/completed 작업 수, DB 상태별 제출 수, 최근 30초 내 응답한 워커, 실패 작업 10개의 사유·시도 횟수가 포함됩니다.

## 7. 채점기 내부 API와 복구

| API | 인증 | 기능 |
|---|---|---|
| `POST /internal/judge/heartbeat` | 채점 토큰 + 워커 UUID | 워커 생존 상태 갱신 |
| `GET /internal/judge/submissions/:id` | 채점 토큰 + 세대/시도 ID | 채점 권한 획득, 소스·제한·전체 테스트 반환 |
| `PATCH /internal/judge/submissions/:id/heartbeat` | 동일 | 제출별 lease 연장 |
| `PATCH /internal/judge/submissions/:id/release` | 동일 | 실행 서비스 장애로 채점하지 못한 lease 반납. 다음 세대로 재등록하며 복구 횟수를 1 쓰고, 이미 5번을 썼으면 SYSTEM_ERROR로 종료 |
| `PATCH /internal/judge/submissions/:id/result` | 동일 | 최종 판정 저장과 XP 정산 |

- `X-Judge-Token`을 상수 시간 비교로 인증합니다. 워커는 `X-Judge-Worker`, 채점 시도는 `X-Judge-Generation`·`X-Judge-Attempt`로 구분합니다.
- PostgreSQL이 상태의 기준입니다. Redis/BullMQ에는 소스·비공개 테스트 대신 `submissionId`, `generation`만 전달합니다.
- DB 잠금과 세대·시도 ID로 중복 claim과 오래된 결과를 거절합니다. 같은 시도의 동일 최종 판정 재전송은 허용하고 다른 판정으로 바꾸는 요청은 거절합니다.
- lease는 60초, 워커·제출 heartbeat는 10초 간격입니다. 워커 목록에서 60초 이상 지난 항목을 정리합니다.
- 복구 작업은 30초마다 실행합니다. 10초 이상 대기한 제출에 큐 작업이 없으면 재등록합니다. 작업이 이미 실패·완료됐는데 DB가 QUEUED이면 SYSTEM_ERROR로 전환합니다. 만료된 JUDGING은 새 세대로 재등록하며, 같은 제출의 lease 복구가 5번을 넘으면 재등록하지 않고 SYSTEM_ERROR로 종료합니다(XP 정답 근거 유지, 재채점 시 횟수 초기화). QUEUED는 회차당 오래된 순으로 최대 1,000건을 확인해 최대 100건을 재등록하고, 만료된 JUDGING 조회는 회차당 100건입니다.
- 작업은 최대 8회 시도하고 5초부터 지수 backoff(총 약 10분)를 적용해 짧은 API 재시작에도 제출이 실패하지 않습니다. 완료 작업은 1,000개, 실패 작업은 5,000개를 보관합니다.
- 실제 실행은 별도 `Judge/` 워커와 go-judge가 담당합니다. Linux namespace·seccomp·읽기 전용 도구 mount, cgroup 기반 프로세스/CPU/메모리 제한과 자식 프로세스 정리, 테스트별 시간·출력 제한을 사용합니다. 실행 시간은 wall time이며 메모리는 cgroup 측정치입니다. 세부 기준은 [Judge 문서](../Judge/README.md)에 있습니다.

## 8. 공통 API와 개발·운영 지원

- `GET /health`: PostgreSQL·Redis 접근과 큐 상태를 확인합니다. 정상은 200, 의존성 장애는 503입니다. 워커 실행 여부는 관리자 운영 조회로 따로 확인합니다.
- `/docs`: Swagger API 문서와 Bearer 인증 입력을 제공합니다.
- DTO 변환·검증, 미등록 필드 거절, UUID 검사, 문제 제목·본문·설명·테스트 입출력과 제출 소스의 NUL·짝 없는 서로게이트 문자 거절(400), 허용 Origin 기반 CORS, Helmet 보안 헤더를 적용합니다.
- 기본 속도 제한은 IP·핸들러별 분당 100회이며 회원가입 5회, 로그인 10회, 비밀번호·사용자 이름 변경 각 5회, 제출 생성 20회입니다. 내부 채점 API는 제외합니다. 카운터는 Redis(`throttle:*` 키)에 저장해 API 인스턴스가 여러 개여도 같은 한도를 공유합니다.
- 프록시 환경은 `TRUST_PROXY`로 신뢰할 프록시 IP/CIDR을 지정합니다. 기본값은 전달 헤더를 신뢰하지 않으며, 웹 프록시는 외부 IP 헤더를 덮어쓰고 요청 전체에 API와 같은 16MiB 제한을 적용합니다.
- 환경 변수 스키마 검증(`NODE_ENV=production`에서는 `.env.example`의 `replace-this…` 예시 비밀키 거절), PostgreSQL SSL 옵션, Redis 주소·계정·DB 설정, API 바인딩 주소·포트 설정을 지원합니다.
- 마이그레이션은 초기 스키마, 버전·채점 시도·해결 기록·감사 로그 추가, 기존 정답 XP/해결 기록 보정과 과거 채점 lease 복구, 공개 예제 실행 출력(`debug_outputs`) 저장, 제출별 XP 정답 근거(`accepted_for_xp`) 보존, 목록 통계·QUEUED 복구·랭킹 인덱스와 대소문자 무시 사용자 이름 고유 인덱스, lease 복구 횟수(`recovery_count`), 커뮤니티 글·답변·추천·저장·팔로우 테이블, 커뮤니티 신고·숨김·조회 기록과 알림 테이블을 제공합니다. 스키마 자동 동기화는 사용하지 않습니다.
- `npm run db:bootstrap:admin -- <email>`: 기존 계정을 관리자로 승격하고 토큰을 무효화합니다. 계정이 없으면 실패합니다.
- `npm run db:seed:demo`: 데모 작성자·A+B 공개 문제·스냅샷과 무작위 비밀번호를 준비합니다. 재실행 시 데모 비밀번호와 토큰 버전이 변경됩니다.
- lint, 단위 테스트, 빌드, PostgreSQL·Redis 기반 E2E 테스트 명령을 제공합니다.

## 9. 화면 연결과 미구현 범위

현재 웹 화면은 홈·랭킹, 전체 랭킹(`/rankings`), 공개 프로필(`/users/:username`), 계정 설정(`/settings`: 비밀번호·사용자 이름 변경), 회원가입·로그인, 공개 문제 검색/필터/상세, 제출·결과 조회, 학습 기록, 문제 생성·수정과 내 문제 관리(기업 전용 포함), 커뮤니티 글·답변(수정·삭제 포함)·추천·저장·팔로우·채택·신고와 팔로잉 필터, 헤더 알림, 관리자 콘솔(`/admin`: 사용자 검색·역할·정지, 감사 로그, 운영 조회)을 연결합니다. 저장한 글은 프로필에서 모아 봅니다. ADMIN은 내 문제 목록에서 공개·초안 상태를 변경할 수 있습니다. 재채점과 커뮤니티 신고 처리의 전용 화면은 아직 없고 API로만 제공합니다.

웹의 문제·제출 목록은 커서로 이어 읽고 클라이언트에서 검색·필터·통계를 계산합니다. 서버가 커서를 제공하지 않는 경우 기존 페이지 조회와 ID 중복 제거를 사용합니다. 429 응답은 `Retry-After`에 따라 같은 요청을 최대 3회 재시도합니다. 커서는 읽기 중 삽입·삭제로 OFFSET이 밀리는 문제를 피하지만, 목록 전체를 하나의 DB 스냅샷으로 고정하지는 않습니다. 장기적으로는 서버 검색·집계 API로 전환해야 합니다.

Refresh token, 서버 로그아웃/전체 세션 관리 API, 이메일 인증, 비밀번호 재설정, 문제 삭제, 사용자 제출 취소, 부분 점수 채점, 대회는 구현되어 있지 않습니다. 커뮤니티는 작성 초안만 브라우저에 둡니다. 코드 분석 문항(정답·해설 포함)은 서버에만 두고, 목록 API는 정답·해설 없이, 판정 API(로그인 기록용·비로그인 연습용)는 답을 낸 뒤 정답·해설을 줍니다. 코드 분석 답변·미션 상태·XP/배지 수령은 서버에 저장합니다. API·기간·재채점 정책·배포 절차는 [미션 문서](../docs/missions.md)를 참고하세요.
