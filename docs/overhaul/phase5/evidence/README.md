# Phase V evidence index and interpretation

The acceptance unit is an immutable **source + current base + actual Actions checkout + Git tree + run/attempt**, with all required jobs actually executed and independent review. See [validation-ledger.json](validation-ledger.json), the feature acceptance comments, and the final stacked PR's post-run receipt. A successful old report does not approve a changed source, base, image, host or operational deployment.

Original ZIP bytes are retained with their GitHub artifact digests. Extracted JSON and selected screenshots make inspection easier. Duplicate paths containing the same bytes have the same Git blob and SHA256. Historical scratch paths inside immutable receipts are preserved as part of the original observation; they are not instructions to depend on those workspaces.

Reports and documentation created after the final CI run can be archived on `overhaul5/final-receipts`, with an immutable commit linked by the final PR acceptance comment. That is an evidence archive, not the tested release source or another automatically merged feature. The receipt always names the separately tested integration head/tree. Evidence-only archival writes do not renew scans, extend policy expiry, or authorize deployment.

## Recompute retained performance observations

From a normal checkout:

```sh
python3 docs/overhaul/phase5/evidence/performance/verify-performance.py
```

The companion uses retained artifacts and source/hash receipts, without a network, Git object history, a database or native execution. It verifies digests, available raw vectors, counts, nearest-rank arithmetic, scope/provenance fields and explicit truncation/unsupported limits. Its isolated-copy and negative-control receipts state exactly what was exercised. Read the adjacent [performance verification guide](performance/README.md) for the required layout.

This offline PASS concerns historical evidence integrity and arithmetic. It is not a fresh application test, reproduction of database row fingerprints without the original database, a new restore, field Web Vitals, a memory-leak conclusion, or a current security approval. The current Runtime gate still fails on evidence drift or the fixed **2026-11-30T00:00:00Z** expiry. Actual required CI and operational acceptance remain separate.

## Counting conventions

Ordinary Playwright totals include85 browser-free unit cases; real browser counts are reported separately. Live Compose cases are a separate suite. Native Node totals include their parent, and the72-row language/scenario matrix is not an additional72 tests to add to that total. Reviewer arithmetic checks are evidence checks, not application tests. Failed baselines, unselected baseline controls, blocked local browsers, superseded source runs and final-source results retain their original classification.

The 32-job/four-trial and24-job/three-wave campaigns each used one API with multiple workers. The new eight-job protocol uses two actual API processes and two actual workers on one disposable host. Those protocols have different boundaries and sample sizes; their counts and latency vectors are never pooled into a capacity claim.
