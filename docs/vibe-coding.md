# 바이브코딩 연습

`/vibe`에서 제공된 TypeScript 프로젝트를 읽고 검색 버그 수정·태그 필터 추가·회귀 테스트 작성을 연습합니다. 첫 버전은 개인 연습이며 기업 테스트 연결과 임의 저장소 가져오기는 포함하지 않습니다.

## 사용자 흐름

1. 로그인하고 과제를 시작합니다. 같은 과제의 진행 중인 연습이 있으면 이어 엽니다.
2. 파일을 편집합니다. 입력이 멈추고 1초 뒤 서버에 저장하며, 이 탭의 sessionStorage에도 계정·응시별 복구 사본을 둡니다. 저장 실패나 수정 버전 충돌은 표시하고 편집 내용을 유지합니다.
3. 코딩 파트너에게 질문합니다. 저장된 프로젝트·최근 대화·공개 테스트 결과만 전달합니다. 제안한 파일은 현재 코드와 나란히 비교한 뒤 적용하고 한 번 되돌릴 수 있습니다. 답변 이후 코드가 바뀌면 예전 변경안을 적용할 수 없습니다.
4. 고정 공개 테스트와 사용자가 작성한 테스트를 실행합니다. 공개 테스트의 정답 비교는 제출 코드 밖에서 수행합니다. 작성한 테스트의 자체 성공 표시는 결과물 점수에 더하지 않습니다.
5. 회고를 선택적으로 적고 제출합니다. 마지막 저장본으로 공개·숨김 기능 검사를 하고 프롬프트·협업 기록을 평가합니다. 제출 이후 파일과 대화는 읽기 전용입니다.

45분이 끝나면 편집·대화·공개 실행을 막고, 이미 서버에 저장된 파일은 이후에도 제출할 수 있습니다. 제출 전에 요청한 실행·평가는 제한 시간 뒤 완료되어도 결과를 저장합니다. 연습 XP나 일반 문제 해결 기록은 변경하지 않습니다.

## 평가

| 항목 | 최대 점수 | 근거 |
|---|---:|---|
| 결과물 | 40 | 공개 5개·숨김 6개 기능 테스트의 통과 비율, 입력 불변성도 검사 |
| 프롬프트 | 30 | 실제 질문의 맥락·문제·제약·완료 기준·후속 지시 |
| 협업·검증 | 30 | 초기·최종 파일, 변경·적용·되돌리기 이벤트, 공개 실행 결과 |

대화 길이·요청 횟수·소요 시간 자체는 점수 기준이 아닙니다. 회고는 자기보고이며 수행 증거로 확정하지 않습니다. 과정 평가의 근거 링크는 실제 메시지·이벤트·실행 UUID만 허용합니다. 과정 점수는 연습 피드백이며 채용 적합성의 자동 판정으로 쓰지 않습니다.

모델은 서버 내부에서 `gpt-6-luna`, reasoning effort `medium`으로 고정합니다. 모델 ID·추론 설정·제공자 키는 공개 화면이나 API에 반환하지 않습니다. OpenAI Responses 호출은 `store: false`, 최대 출력 8,192토큰, 60초 제한, 자동 재시도 없음입니다. 구현 근거는 [모델 문서](https://developers.openai.com/api/docs/models/gpt-6-luna)와 [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)입니다.

평가 연결이 실패하면 기능 점수와 제출을 보존하고 과정 점수·총점은 미완료로 표시합니다. 제출 후 과정 평가를 다시 요청할 수 있습니다. 실행기 장애는 학습 실패 판정으로 바꾸지 않고 파일을 보존한 채 재시도를 안내합니다.

## 실행과 환경 변수

`Back/.env` 또는 배포 서버의 환경 변수에 다음을 설정합니다. API 키는 저장소에 커밋하거나 `VITE_*`에 넣지 않습니다.

```dotenv
OPENAI_API_KEY=
VIBE_AI_MODEL=gpt-6-luna
VIBE_SANDBOX_URL=http://127.0.0.1:5050
VIBE_SANDBOX_TOKEN=실행기의_ES_AUTH_TOKEN과_같은_값
```

마이그레이션 실행 후 API와 프론트를 시작합니다. 실행기는 기존 `Judge/runtime`의 go-judge·Node·esbuild를 사용합니다. 로컬 전체 Compose에 키를 전달하려면 `OPENAI_API_KEY` 환경 변수를 셸에 설정하거나 ignored `.env`/`--env-file`을 사용합니다. 운영은 Dokploy 등의 서버 환경 변수에 키를 주입합니다. `deploy/compose.yaml`이 API에만 키를 전달하며 프론트와 실행기에는 전달하지 않습니다.

API가 인증된 go-judge에 한정된 실행 요청을 보내므로, API도 사설 sandbox 네트워크에 연결됩니다. 제출 코드를 API 프로세스·호스트 셸에서 실행하지 않습니다. 별도 실행 호스트를 쓸 때는 해당 호스트의 사설 URL·토큰을 설정합니다. 공개 포트로 실행기를 노출하지 않습니다.

프론트 nginx의 API 응답 대기는 150초입니다. 실행과 과정 평가를 이어 처리하는 제출 요청을 위해 외부 프록시의 응답 대기도 이에 맞춰 설정하세요. 중간 프록시가 먼저 연결을 끊은 경우 작업이 서버에서 완료될 수 있으므로 응시 기록을 다시 열어 결과를 확인합니다.

파일 이름은 과제에서 허용한 3개로 고정하고 파일당 UTF-8 30KB를 허용합니다. 실행기에서만 고정된 esbuild 명령으로 다중 파일을 번들하고 Node로 실행합니다. Linux·seccomp·CPU/메모리/pids cgroup을 확인한 뒤 실행하며, 컴파일 512MiB·CPU 5초/wall 10초, 개별 실행 512MiB·CPU 1초/wall 2초, 출력별 16KiB, 전체 실행 45초 제한입니다. 생성한 캐시 파일은 실행 성공·실패 모두 정리합니다.

## 기록과 한도

`vibe_attempts`에는 소유자, 과제 버전 ID, 파일, 대화·변경안, 실행·변경 이벤트, 평가, 서버 내부 모델 설정을 저장합니다. 다른 계정의 응시는 404입니다. 비밀번호 변경 강제·정지·세션 무효화는 기존 인증 가드를 따릅니다. 과제 버전 ID는 게시 후 변경하지 않습니다.

- 새 연습: 계정당 최근 24시간에 5개, 목록은 최근 20개
- 대화: 연습당 20회, 실패 요청도 포함, 메시지당 4,000자
- 공개 실행: 연습당 20회, 과정 평가: 최초 제출 포함 최대 3회
- 파일 변경: 150회까지, 이후 저장본 제출 가능
- 외부 작업: DB 잠금으로 전체 최대 2개 동시 처리, 같은 응시는 한 번에 하나
- 저장·적용·실행은 revision 일치를 검사하며, 180초가 지난 작업의 늦은 응답은 새 편집을 덮어쓰지 못함

브라우저 복구 사본은 서버 저장·백업을 대신하지 않습니다. 서비스 밖에서 사용한 도구·대화는 평가 근거에 포함되지 않습니다. 연습 기록은 현재 자동 삭제하지 않으므로 보관 기간 정책은 기업 평가로 확장하기 전에 정해야 합니다.

## 검사

```sh
npm run check --prefix Back
npm run check --prefix Front
npm run test:e2e --prefix Back -- test/vibe.e2e-spec.ts
cd Front
npx playwright test tests/vibe.spec.ts --project=chromium
```

백엔드 통합 검사는 기존 runner가 생성·삭제하는 일회용 DB를 사용하며 AI·실행기는 테스트 대역으로 교체합니다. 실제 모델·실행기 검증은 별도 로컬 테스트 계정과 일회용 데이터베이스로 수행합니다.
