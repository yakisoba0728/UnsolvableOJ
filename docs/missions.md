# 서버 미션과 보상

기존 못풀준 미션 화면의 목표와 보상에 맞춰 PostgreSQL을 상태의 기준으로 사용합니다. 클라이언트가 보낸 진행률·정답 여부·XP·사용자 ID·시각은 보상 근거로 받지 않습니다. 인증된 계정과 DB 시각으로 조회·수령을 처리합니다.

## 규칙

| 미션 | 서버에서 확인하는 근거 | 보상 | 초기화 |
|---|---|---|---|
| 일일 | 오늘 제출한 서로 다른 문제 5개의 정답 근거 | 50 XP | 한국 시간 자정 |
| 코드 분석 | 오늘 서로 다른 분석 문제 5개에 답 제출(오답 포함 학습 참여) | 80 XP | 한국 시간 자정 |
| 심야 코더 | 00:00 이상 06:00 미만 제출 3건, 학습 판정 완료 | 심야 코더 배지 | 한국 시간 자정 |
| 주간 | 이번 주 제출한 서로 다른 문제 10개의 정답 근거 | 300 XP | 한국 시간 일요일 00:00 |
| 커뮤니티 | 이번 달 작성한, 현재 남아 있는 SOLUTION 글 2개 | 150 XP | 한국 시간 매월 1일 |
| 연속 학습 | 학습 판정 완료된 제출이 있는 날 7일 연속 | 120 XP + 7일 연속 학습 배지 | 연속 기록 시작일마다 한 번 |
| 오늘의 보너스 | 서버가 지정한 미해결 공개 문제를 오늘 처음 해결 | 지정 시 난이도 기준 10/20/40/80/160 XP 추가 | 한국 시간 자정 |

일일·주간 미션에서 같은 문제는 해당 기간 안에서 한 번만 셉니다. 다른 날 다시 푼 문제는 그날의 학습으로 인정합니다. 연속 학습은 오늘 제출 전에도 어제까지 이어진 기록을 유지하며, 날짜를 하나 온전히 놓치면 새 기록을 시작합니다. 7일→8일로 늘어난 동일 연속 기록은 추가 보상을 주지 않습니다.

학습 판정은 정답·오답·컴파일/실행 오류·시간/메모리/출력 초과입니다. 최초 채점 대기, 서버 오류, 취소만으로는 심야/연속 미션을 달성하지 않습니다. 코드 분석 문제·보기는 기존 학습 콘텐츠를 유지하며 서버의 정답표와 일치하는지 회귀 테스트로 확인합니다. 이 콘텐츠는 시험용 비밀 문제은행이 아닙니다.

보너스 문제는 첫 조회 때 하루 한 번 고정 배정합니다. 모든 공개 문제를 이미 해결했다면 비활성 상태로 표시합니다. 보상은 지정 시 난이도에 따라 고정되며, 문제 수정 때문에 기본 첫 정답 XP가 바뀔 수 있으므로 기존의 확정되지 않은 “XP 2배” 문구 대신 실제 추가 XP를 표시합니다.

## 수령·완료 기록과 동시성

- `mission_states`: 계정·미션·기간별 유일한 상태, 진행도, 최초 관측 완료 시각, 보상 스냅샷, 수령 시각, 보너스 문제 ID.
- `user_badges`: 계정·배지별 유일한 획득 기록. 같은 배지를 여러 날 달성해도 중복 생성하지 않습니다.
- `analysis_attempts`: 계정·문제·한국 날짜별 답변 기록. 서버가 정오답을 판정하며, 반복 제출은 그날 같은 문제 한 건만 갱신합니다. 과거 정답 경험은 이후 오답을 제출해도 유지합니다.
- GET `/api/v1/missions`와 수령 시 서버 원본 기록을 집계하여 현재 기간의 상태를 갱신합니다. 백그라운드 작업이나 브라우저 방문 전 과거 기간의 자동 보상 지급은 없습니다. `completed_at`은 원본 사건 시각이 아닌 서버가 완료를 관측한 시각입니다.
- 계정별 PostgreSQL 트랜잭션 advisory lock과 유일 제약으로 다중 탭·동시 요청을 직렬화합니다. 수령 기록, XP/레벨 변경, 배지는 하나의 트랜잭션으로 저장합니다. 중간 실패는 전부 롤백합니다.
- 응답이 유실된 뒤 같은 상태 ID로 다시 수령하면 `alreadyClaimed: true`와 기존 수령 결과를 반환하며 XP를 더하지 않습니다. 기간이 지나도 이미 수령한 영수증은 다시 조회할 수 있습니다.
- 미수령 보상은 현재 근거로 재검증합니다. 마지막 정답이 오답으로 재채점되거나 풀이 글이 삭제/분류 변경되면 완료 상태를 해제합니다. 재채점 대기/서버 오류 중 보존된 `accepted_for_xp` 근거는 기존 OJ 정책과 동일하게 인정합니다.
- **수령 완료된 미션 보상은 이후 재채점·글 삭제로 회수하지 않는 달성 보상 정책**입니다. 기존 문제 풀이 XP의 회수 정책은 유지합니다. 이 정책은 머지 전 팀 검토 항목입니다.
- 시즌 링은 “이번 달 보상 수령 횟수 / 15”로 표시합니다. 브라우저의 과거 진행률 추정값을 누적 보상으로 오해하지 않도록 문구를 변경했습니다. 시즌 링 자체의 추가 보상은 기획에 금액/종류가 없으므로 새로 만들지 않습니다.

## API

모두 JWT가 필요하며 사용자 ID는 토큰에서만 가져옵니다.

| API | 내용 |
|---|---|
| `GET /api/v1/missions` | 현재 미션, 완료/수령 상태, 마감, 시즌 수령 횟수, 획득 배지 |
| `POST /api/v1/missions/:stateId/claim` | 완료 근거 재검증 후 보상 수령; 타인 ID 404, 미달성/기간 만료 409 |
| `GET /api/v1/missions/analysis/attempts` | 문제별 최근 답변 및 과거 정답 여부 |
| `POST /api/v1/missions/analysis/:questionId/attempts` | `{ "selected": 0 }` 형식으로 보기 제출, 서버 정오답 판정 |
| `GET /api/v1/users/me` | 기존 프로필에 `badges` 추가 |

코드 분석의 로그인 전 연습은 로컬에 유지합니다. 기존 로컬 기록은 출처를 검증할 수 없으므로 서버 XP로 소급 지급하지 않습니다. 서버 저장 실패 시 정답 확인을 완료한 것처럼 표시하지 않고, 선택한 답을 유지한 채 재시도할 수 있게 합니다.

## 검토 및 친구 서버 반영 요청

1. 미션별 목표·XP, 한국 시간/일요일 주 시작, 코드 분석은 오답도 참여로 인정하는 규칙, 수령 후 미션 보상을 회수하지 않는 규칙을 검토해 주세요.
2. PR의 CI를 확인한 뒤 main에 머지해 주세요. 운영 DB를 백업하고 이전 정상 커밋을 기록해 주세요.
3. 기존 Dokploy Compose 서비스와 PostgreSQL 볼륨을 유지한 채 Front·Back을 같은 커밋으로 재빌드/배포해 주세요. 새 서버나 DB를 만들 필요는 없습니다.
4. Back 시작 시 `Missions1793000000000` 마이그레이션이 적용됩니다. 기존 마이그레이션은 수정하지 않습니다. 별도 환경 변수나 Redis 설정은 필요하지 않습니다.
5. `/api/v1/health`, 로그인 후 미션 목록, 분석 답변 저장, 미션 수령, 새 브라우저 로그인 후 동일 수령 상태, 프로필 XP·배지를 확인해 주세요. 운영 검증 계정과 데이터는 서버 담당자가 정해 주세요.
6. 문제가 생기면 우선 호환 가능한 이전 앱 이미지로 되돌립니다. 미션 기록이 존재하면 migration down은 의도적으로 거절합니다. 수령 내역만 지우면 중복 지급될 수 있으므로 운영 데이터 삭제나 `down -v`로 복구하지 마세요.

## 검증 명령

```sh
npm run check --prefix Back
npm run check --prefix Front
cd Back
# 기존 통합 테스트 실행기가 일회용 DB를 생성/삭제합니다. 운영 URL을 사용하지 마세요.
npm run test:e2e
npm run test:migrations
cd ../Front
npm run test:e2e -- --project=unit --project=chromium --workers=2
```

미션 통합 테스트는 실제 PostgreSQL과 인증/컨트롤러/유효성 검사를 사용하며 채점 워커 없이 실행할 수 있습니다. 에디터 코어는 변경하지 않았고 기존 에디터 회귀 테스트를 함께 실행합니다. 테스트 통과는 모든 환경에서 결함이 없다는 보장이 아니며 배포 후 검증은 별도로 필요합니다.
